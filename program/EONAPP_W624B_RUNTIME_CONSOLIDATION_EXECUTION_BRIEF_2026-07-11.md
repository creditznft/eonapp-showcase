# W624B — EON City Runtime Consolidation Execution Brief

Date: 2026-07-11  
Starts from: W624A Productive Nocturne checkpoint  
Purpose: create one authoritative City boot/access/recovery shell before W624C final Command District production.

## Frozen W624A authority

W624B must import and preserve `assets/js/city/eon-city-art-bible.js`. It may not redesign the palette, cast, architecture language, productive-RPG truth contract, target budgets, target frames, reject list, or scoring thresholds.

W624B produces runtime architecture, not final art. Owner target-frame review remains required before W624C final-quality art production.

## Required implementation

### 1. One authoritative public City path

- Canonical public destination remains `/eoncity`.
- One Babylon runtime module owns heavy City creation and disposal.
- Compatibility aliases may redirect, but may not instantiate a competing renderer.
- The lightweight guest preview remains honest and cannot silently boot the authenticated heavy renderer.

### 2. One access gate

Create one explicit state resolver for:

- guest/light preview;
- checking session;
- authenticated/heavy City allowed;
- expired session;
- unsupported WebGL/device;
- recoverable server or asset failure.

No client query string, localStorage flag, fake cookie, demo password, or direct renderer URL may grant authenticated heavy access.

### 3. One boot state machine

Use a deterministic state sequence:

1. `idle`
2. `checking-access`
3. `preview` or `loading-shell`
4. `loading-core`
5. `core-ready`
6. `streaming-detail`
7. `ready`
8. `degraded` or `recoverable-error`
9. `disposed`

Every state has visible copy, timeout behavior, retry/exit actions, and machine-readable evidence.

### 4. Fullscreen City shell

- Minimal Productive Nocturne HUD only.
- Persistent desktop: objective, nearby useful destination, Share, Menu.
- Persistent mobile: objective, interact, movement/camera, Menu.
- No duplicate global app sidebar over the heavy renderer.
- Profile, settings, accessibility, exit, and recovery remain reachable from Menu.

### 5. Deterministic asset manifest

Create a versioned manifest for:

- core geometry and materials;
- player/EONBOT/NPC placeholders or source-authored art;
- target-frame references;
- optional detail cells;
- audio groups;
- cache version and integrity metadata.

The manifest must distinguish core-required, optional-streamed, and fallback assets. No remote art dependency is allowed.

### 6. Recovery contract

Prove focused source/runtime behavior for:

- cold boot;
- warm boot;
- refresh during load;
- logout;
- session expiry;
- failed optional asset;
- failed required asset;
- WebGL context loss and restore;
- low-memory or quality downgrade;
- background/foreground resume;
- clean disposal and re-entry.

### 7. Truth boundaries

- Loading percentages must represent real completed stages, not timers.
- A degraded City must say what is unavailable.
- No fake jobs, fake NPC work, fake economy, or private data in scene metadata.
- Source tests cannot certify visual quality or real device performance.

# W624J Execution Brief — Sharing Center and Collaboration Boundary

Date: 2026-07-11  
Prerequisite: W624I Genuine Agent Theatre

## Mission

Create one review-first Sharing Center that unifies safe milestone cards, sanitized previews, signed invitations and collaboration boundaries without exposing private product state or mixing ordinary sharing with referrals/rewards.

## Required share families

1. Project milestone card from an explicitly selected saved project milestone.
2. Sanitized preview handoff containing only user-reviewed public fields.
3. Signed public invite using the existing real invite/signing authority when available; otherwise show an honest unavailable boundary.
4. Collaboration invitation only for a surface that genuinely supports collaboration.
5. City postcard/share handoff using existing public-safe City output.
6. Plain system share/copy/download fallback with no tracking requirement.

## Review and privacy contract

- Build a finite manifest before sharing.
- Show exactly what will be included and excluded.
- Require explicit review and a separate final share action.
- Never include chat history, prompts, Vault data, provider keys, attachments, private files, hidden project fields, account IDs, payment data or job raw responses.
- Never auto-post, auto-invite, auto-copy or auto-open social networks.
- Referral invite context and EONKEY status remain a separate labelled programme; ordinary shares must not imply rewards.
- No click/impression/social-post tracking.

## Runtime and compatibility

Preserve W624B–W624I, the stable test/archive contract and the Command District expansion block. The Sharing Center may open native routes or the platform share sheet only after explicit review; it must not start work or alter billing/referral/reward state.

## Acceptance

- Focused manifest, sanitization, signing-authority, collaboration and negative privacy tests.
- Honest unavailable states when signing or collaboration authority is missing.
- Browser proof for review-first behavior and seeded private-field exclusion.
- Stable `npm run verify:codex-predeploy` extended without renaming.

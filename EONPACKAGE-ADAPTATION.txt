- EONAPP.ch now uses a stronger browser identity format through:

What was intentionally rejected
-------------------------------
1. Full P2P storage (kubo-rpc-client / IPFS PubSub)
- P2PStorageSystem in eonpackage uses kubo-rpc-client and IPFS PubSub.
- Both require Node.js. Neither runs in a browser natively.
- GunDB replaces this role: it is CDN-loadable, browser-native, and already live.
- Decision: GunDB IS the P2P layer. IPFS PubSub is NOT.

2. Wallet and token systems as user-facing friction
- Smart contracts exist (11 EONLite contracts, fully tested).
- But wallet connect is NOT a first-session requirement.
- The app runs fully without a wallet. Token claims are unlocked on the user's terms.
- Decision: local-first first, on-chain optional.

3. P2PTournamentService wallet multi-sig
- eonpackage's tournament service requires wallet address signatures for result multi-sig.
- This is not portable to EONAPP.CH without wallet-connect UX.
- Decision: use UID-based tournament lite (async duels + GunDB leaderboard) instead.

4. Large React/TSX feature surfaces
- eonpackage contains logic worth learning from
- the actual React components do not belong in this vanilla static architecture

Multiplayer decision (CEO-level, final)
----------------------------------------
After auditing `P2PMultiplayerService_V5.ts` in eonpackage:

Tier 1 — Async challenge duels (BUILT, URL-first):
- Module: `assets/js/utils/p2p-multiplayer.js` ✅ COMPLETE
- Deterministic seeds: both players play same seed, scores compared locally
- Challenge URL carries: gameId + seed + score + challengerUID + expiry (btoa encoded)
- No WebRTC, no NAT issues, works across devices without live connection
- GunDB is optional enhancement only — all challenge flows work URL-only
- Wired into: reaction-sprint, word-blitz, orbit-survivor, memory-chain, void-raider, neon-dash, merge-grid, color-sprint, tap-reactor

Tier 2 — Nostr relay discovery (BUILT, replaces GunDB):
- Module: `assets/js/utils/p2p-nostr.js` ✅ NEW
- Protocol: Nostr NIP-01 over WebSocket to public relays
- Relays: relay.damus.io, nos.lol, relay.snort.social, nostr.wine, relay.nostr.band, relay.primal.net
- 50+ independent public relays — no single point of failure
- Ephemeral keypair per player (generated once, stored in localStorage)
- Events: kind 20001, tagged with #t:eon-game:{gameId}
- No hosting required by EONAPP. No CDN script needed (pure WebSocket).
- Status: optional discovery layer, activated when browsing live challenges

Tier 3 — Real-time WebRTC 1v1 (Phase 2, future):
- Module: planned `assets/js/utils/p2p-room.js`
- Signaling: Nostr DM (NIP-04) or URL exchange — NO GunDB needed
- STUN: Google (stun.l.google.com:19302) — free, permanent
- Only needed for specific live PvP games

GunDB status (DEPRECATED from required stack):
- Reason: community relays (relay.peer.ooo, peer.wallie.io) are volunteer-hosted, volatile
- Nostr provides better decentralization (50+ relays, cryptographic signing)
- URL-only challenges work with ZERO relay dependency (always-on)
- GunDB code kept in p2p-multiplayer.js but clearly marked optional, wrapped in try/catch
- Decision: Do NOT add any new GunDB dependencies

Explicitly NOT porting:
- P2PStorageSystem (kubo-rpc-client, requires Node.js)
- Tournament wallet multi-sig (wallet signatures add legal drag)
- IPFS PubSub signaling (requires Node.js, kubo daemon)

Hard rule going forward
-----------------------
If a feature from eonpackage needs:
- shared mutable truth
- anti-fraud enforcement
- wallet signatures
- global persistence
- backend moderation

it is not a phase-1 EONAPP.ch feature.

EONAPP.ch wins by being:
- static
- fast
- local-first
- viral
- P2P-connected via URL challenges + Nostr discovery (no central server)
- honest about what is and is not real

The P2P layer (Nostr) is the exception: it adds shared discovery without central authority.
Nostr events are ephemeral, signed, and eventually-consistent — it is a broadcast channel,
not a ledger. The trust anchor remains the signed challenge URLs and local vault state.

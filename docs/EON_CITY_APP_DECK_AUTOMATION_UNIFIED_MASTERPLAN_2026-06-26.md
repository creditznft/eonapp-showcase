# EON City + App Deck + Automation Unified Masterplan

**Status:** locked product architecture, coding-first program.  
**Production repair:** C-00 is explicitly deferred until the source waves below are merged into a tested Preview build. It remains mandatory before any production claim or payment activation.

## Product thesis

EONAPP is a local-first operating environment that wraps useful AI work in a premium spatial City. It is not a metaverse dashboard, an unbounded autonomous-agent system, a generic app-store clone, or a token/reward economy.

Users choose an outcome, a role, a service boundary, or a repeatable Blueprint. EONBOT prepares work in the foreground. A future connection can only act inside a declared permission class and an explicit review policy. EON City visualises safe summaries of that process without rendering private prompts, keys, files, raw AI output, or invented agent activity.

## Four App Deck categories

| Category | User promise | Current W362 behavior | Future boundary |
|---|---|---|---|
| Workrooms | Start from an outcome, not a blank chat | Opens a safe foreground Chat prefill | More guided native work surfaces and local project templates |
| AI Crew | Choose a visible role: Coordinator, Researcher, Builder, Creator, Reviewer | Opens a role-scoped foreground Chat prefill | City character state may reflect real foreground receipts only |
| Connections | Understand a service and its permission scope | Planned-only cards; no OAuth, token, credential, or account access | Scoped connection broker, revocation, expiry, policies and receipts |
| Blueprints | Turn repeat work into a reviewable workflow | Prefills an Automation goal; user must still create the local draft | Official tested templates; later curated partner packs only |

No open developer marketplace, arbitrary third-party code, user-uploaded agent code, financial workflow, or commercial entitlement is part of the current program.

## Art and character rules

- Use original EON concepts. Do not copy third-party game art, characters, UI, signage, sounds, meshes or animations.
- Produce concept sheets before meshes: Operator, EONBOT, Builder, Researcher, Creator, Reviewer, Realm Keeper and ambient citizens.
- Hero characters use rigged GLB assets with idle/walk/turn/greet/terminal interactions. Ambient population uses lower-detail, instanced variants.
- Use authored landmark kits: command architecture, human-scale street props, transit, maintenance drones, wayfinding, vegetation and weather layers.
- Generated visual concepts are draft inputs only. Every shipped binary needs source, licence/provenance, performance tier, LOD and removal path recorded.
- Provider characters never pretend to work. Their City state can show only configured/ready/foreground-working/review-needed/completed/blocked based on local receipts.

## Quality gates

- No City entrance makes a first-time user believe the 2D map is the flagship experience.
- City Lite, Babylon and Three.js share landmark names, state and return paths.
- App Deck uses plain language: Workrooms, AI Crew, Connections and Blueprints.
- A Blueprint does not create an automation until the user explicitly creates a local draft.
- Every future action has a category and policy language before any integration code.
- All private data stays outside City renderers and App Deck selection receipts.
- Asset budgets are defined before shipping heavy art files.
- C-00, real-device proof and visual certification occur before production is described as current.

# W660P — EONCITY: THE LIVING NEXUS

## CEO decision

The final direction is **Option 3: Living Nexus Hybrid**.

Build order:

1. **Option 1 foundation** — authored, reliable, productive Core City.
2. **Option 2 controlled experimentation** — deterministic streamed Expanse cells and rare authored encounters.
3. **Unified hybrid** — Core, Expanse and My Realm connected by EON NEXUS and verified productive outcomes.

Final formula:

> **Handcrafted Core + Living Streets + Seeded Expanse + Rare Realms + Productive Missions + Persistent Personal Transformation**

This is a dense micro-open-world, not an unbounded imitation of GTA. It must feel open, alive and replayable while remaining fast, truthful, safe and useful.

## Three destinations

### EONCITY CORE

The authored nine-district city remains the reliable centre:

- Command Centre
- Creator Atrium
- Forge Bay
- Project District
- Device Lab
- Orientation Hall
- Trade Dome
- Workstation
- Command District / Nexus anchor

Every district must be visibly distinct, physically connected and functionally useful. Terminals open real EONAPP surfaces only after review. Pathfinder, EONBOT, NPCs, transit, docking stations, weather, wall fading, interiors and world activity belong here.

### THE EXPANSE

A deterministic streamed open-world layer surrounding the Core. The first proof is always a bounded 3×3 residency window around the player.

Every cell requires:

1. connected road grammar;
2. visual identity;
3. building composition;
4. activity layer;
5. gameplay purpose;
6. a safe local navigation route.

Cells are deterministic from a public-safe seed and coordinates. They never contain private project content, credentials, chat, prompts, files or account data. They do not fetch arbitrary remote assets or navigate automatically.

### MY REALM

A private local destination that reflects verified work as visual transformation. It is not a fake economy, public marketplace, hidden social feed or second project store.

Examples:

- a real project shell lights a Project habitat;
- a verified Local AI self-test activates a Device Lab signal;
- a creator guide prepares a gallery bay;
- a real encrypted Capsule seals an Archive sanctum;
- a reviewed restore illuminates a return path.

Only opaque bounded receipts and public-safe transformation ids may enter this layer.

## Two player modes

### Focus Mode

- quick access to terminals and Command Room;
- minimal HUD and direct destination review;
- fast travel only after explicit confirmation;
- productivity first;
- no background execution.

### Explore Mode

- walking, transit and physical discovery;
- EONBOT companion behaviour;
- functional NPC encounters;
- weather, traffic, schedules and world events;
- recording and sharing through the one global Sharing Center;
- gameplay first without hiding the real EONAPP action boundary.

Both modes share one player, one EONBOT, one world state, one project store, one task store, one canvas and one render loop.

## Core gameplay loop

> Explore the world → EONBOT or an NPC identifies an opportunity → inspect it → EONAPP proposes a real action → review → confirm → complete the action in the native surface → return with a bounded verified receipt → transform the location → record it in Atlas → reflect it in My Realm.

No City surface may claim that generation, backup, automation, payment, reward or work completion occurred without authoritative evidence.

## Vertical slice acceptance loop

The first complete hybrid slice must prove:

1. leave Core City;
2. enter the Expanse;
3. discover a landmark;
4. meet a functional NPC;
5. review a real productive mission;
6. complete the action through EONAPP;
7. transform the location from a verified bounded receipt;
8. record the result in Atlas;
9. return through Nexus;
10. see the result reflected in My Realm.

# Addictive AAA Games + Engine Experiences Roadmap

Date: 2026-04-22
Scope: post-launch product expansion for EONAPP.CH
Constraint: only AAA-grade game foundations count for this phase

---

## Executive Direction

This roadmap is now constrained to the existing high-code-volume game foundations.

What counts:
- games with strong existing systems depth and expansion headroom
- game-adjacent experiences that behave like engines, simulators, directors, or replay spaces
- loops that can hold users for hours or days, not one-shot utility outputs

What does not count:
- small novelty games
- standalone static tools with one result and no long-term progression
- throwaway prototypes that do not connect to a flagship game loop

Final product stance:
- build five flagship browser games into endless retention systems
- attach game-grade companion experiences that feel as deep as games
- keep lootbox progression, collectibles, challenge links, and social replay as the shared meta layer

## Product Thesis

Target loop quality:
- 60-second action clarity
- 10-minute tactical depth
- 60-minute mastery runway
- 30-day return reason

Design rules:
- skill and strategy first
- lootboxes enhance collection and identity, not pay-to-win power ceilings
- randomness must create stories, not confusion
- every session should generate one of these outputs:
	- progress
	- loot
	- a challenge artifact
	- a replay artifact
	- a build decision

---

## Shared Meta Layer (Mandatory Across Flagships)

All five flagship games should converge on one shared retention spine.

### 1) Endless Run Structure

- endless mode, seasonal mode, and daily seeded mode
- deterministic run seeds where possible
- rotating mutators every day/week
- failure must still grant partial progression

### 2) Lootbox + Collectible Economy

- users earn lootboxes from play, streaks, boss clears, rank milestones, and challenge participation
- lootboxes grant cosmetic collectibles, faction artifacts, profile badges, scene skins, replay frames, and mergeable item classes
- ultra-rare drops must be visible and shareable without becoming balance-breaking combat power
- all flagship games should emit rewards into the same vault-facing collectible model

Lootbox policy:
- no purchase-first dependency for core fun
- ad-rewarded boxes stay bonus-only and are enabled only after domain/app deployment is finalized
- rarity should create identity, aspiration, and social proof, not economic lockout

### 3) Challenge + Ghost Layer

- every flagship game should create signed shareable challenge artifacts
- ghost data, score snapshots, run seeds, and build codes should be exchangeable across devices
- challenge links must remain URL-first and local-safe even before backend activation

### 4) Social Rivalry Layer

- streaks
- rival lists
- revenge runs
- same-seed duels
- guild or syndicate seasonal comparisons where game theme supports it

### 5) Creator Layer

- creator-authored challenge presets
- creator loot drops or seasonal signatures
- replay highlight export packs
- daily featured creator scenario rotation

## Engine Experiences (Replace the Old Tool Plan)

These are not ordinary tools. They are long-session companion experiences that run on top of the game systems.

### 1) Build Forge

Purpose:
- a living build simulator for all flagship games

Why it is game-grade:
- users do not just select loadouts; they test upgrade paths, rarity combinations, and challenge presets
- build URLs become social artifacts
- top builds feed directly into challenge links and replay comparison

Retention hooks:
- saved build trees
- creator build drops
- patch delta views

### 2) Ghost Theater

Purpose:
- replay, compare, and branch alternate decisions from real runs

Why it is game-grade:
- users watch, fork, annotate, and challenge against ghost runs
- feels like a strategy sandbox, not a viewer

Retention hooks:
- alternate-route playback
- creator commentary tracks
- revenge run queue

### 3) Run Director

Purpose:
- a scenario engine that generates daily runs, mutators, door choices, and route branches

Why it is game-grade:
- this is the "life destiny labyrinth" direction, but grounded in the existing flagship loops
- users choose doors, routes, modifiers, risks, and rewards that feed into real playable sessions
- can act as the front-end narrative shell for multiple flagship games

Retention hooks:
- daily labyrinth seeds
- limited-time route branches
- streaks for survival and perfect routing

### 4) Meta Lab

Purpose:
- a live sandbox for balance prediction, economy pressure, and rarity simulations

Why it is game-grade:
- it becomes a playground for theorycrafters and creators, not an internal admin tool
- users can test "what if" patch states and share outcome boards

Retention hooks:
- community patch meta contests
- top theory builds
- pre-season speculation boards

### 5) Session Coach Arena

Purpose:
- deterministic run review with score loss breakdowns, route inefficiency analysis, and build advice

Why it is game-grade:
- framed like training mode, not a utility report
- users improve, rematch, and re-enter gameplay immediately

Retention hooks:
- mastery ladders
- self-challenge rematches
- friend-vs-friend coaching comparisons

Execution rule for all engine experiences:
- they must ingest data from flagship games
- they must emit shareable artifacts back into flagship games
- if an experience cannot clearly do both, it does not ship

## Hosting Decision For This Roadmap

Final hosting direction for this phase:
- GitHub remains source control
- Cloudflare Pages remains the primary live host
- Cloudflare Worker/D1/KV/R2 remains the backend spine when backend activation is turned on
- Arweave is reserved for immutable archives, seasonal snapshots, replay bundles, and special collectible exports

Why this stays true:
- the app already needs HTTPS, fast iteration, and smooth Git push deployment
- Cloudflare Pages matches the current static-first launch path
- Worker services are only required when shared online state becomes necessary
- Arweave is valuable, but not as the primary live host for fast-changing flagship games

Operational rule:
- do not block flagship game expansion on full backend rollout
- ship local-first and URL-first loops first, then enable Worker-backed shared layers where they add real value

## Success Metrics

Flagship targets:
- D1 retention: >= 35%
- D7 retention: >= 15%
- average session time: >= 18 minutes on flagship games
- weekly return rate: >= 22%
- challenge-share conversion: >= 8%
- replay/watch rate: >= 20%
- lootbox open-to-return-session correlation: positive after week 2

Engine experience targets:
- at least 35% of flagship users touch one engine experience within 7 days
- at least 20% of engine experience users re-enter gameplay from that experience in the same session
- at least 10% of engine experience sessions create a shared artifact

Kill rule:
- if a feature does not improve retention, session depth, share rate, or return-to-game rate within 2 release cycles, cut or redesign it

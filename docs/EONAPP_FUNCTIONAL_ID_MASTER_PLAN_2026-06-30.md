# EONAPP Functional-ID Master Plan

This document replaces wave number ambiguity. Wave numbers may remain as implementation history, but release decisions must use functional IDs.

## City

- `CITY-ROUTE` — one canonical public route: `/eoncity`; retire legacy Realm/old City aliases with cache proof.
- `CITY-ENGINE` — staged boot, asset lifecycle, WebGL health, memory, GPU and frame-time budgets.
- `CITY-ART` — original art direction, landmarks, asset provenance, LODs and visual review.
- `CITY-WORLD` — street/skyline/weather/lighting/audio/life layers.
- `CITY-NPCS` — original, readable, animated character set with truthful status behavior.
- `CITY-WORKSPACE` — real in-world EONAPP tool surfaces and same-location return.
- `CITY-MOBILE` — landscape Explore Mode plus portrait Companion Mode.
- `CITY-SHARE` — safe manual City Postcards and Remix cards, never silent publishing.
- `CITY-QA` — visual, functional, GPU and device certification.

## Product foundations

- `AUTH-GOOGLE` — green by owner-confirmed production login/logout; retain release evidence only.
- `SYNC-BASIC` — consented D1 sync only for approved low-risk data; require two-device, deletion and recovery proof.
- `PWA-RECOVERY` — install/update/rollback proof with local-data survival.
- `NOTIFY-CENTER` — in-app Activity Center first; no push until consent/delivery/unsubscribe proof.
- `EONBOT-JOBS` — transparent local job receipts; no fabricated work status.
- `SHARE-PACK` — user-approved manual sharing only.
- `REFERRAL-LEDGER` — disabled until backend ledger, consent, anti-abuse, billing/reversal and support proof.
- `TELEGRAM-REPURPOSE` — onboarding, updates, support and deep links; no rewards, gates or wallet behavior.
- `TRADE-INSIGHT` — non-financial research/analysis only; no execution, prediction market, profit or portfolio claims.
- `COMMERCE-BILLING` — merchant onboarding can begin; hosted checkout integration happens only after core launch proof.
- `SECURITY-A11Y` — security, privacy, accessibility, truth-copy and dependency closure.
- `RELEASE-PROOF` — fail-closed evidence board and CEO approval.

## Option B — private project districts

Every user project may become an expandable private City district only after explicit user action and City-safe label approval. The City render plan may use bounded visual geometry and approved task-card state. It must never expose the project identifier, title, files, prompt, secret, private dataset, account state, or any public route by default.

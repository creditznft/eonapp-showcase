# W367 — Three.js Spatial Command Space

## Purpose

W367 develops `/eoncity/tour` as the premium **Spatial Command Space** of the same local EON City. It is an optional Three.js presentation layer, not a second game, account dashboard, provider console, agent executor, or cloud workspace.

## Delivered source work

- A renderer-safe command projection with a finite City mission card, finite City mode identifiers, sanitised local cue count, bounded work lanes, and three deliberate camera presets.
- Three.js camera transitions for **Arrival vista**, **Command Centre**, and **City skyline**.
- An original procedural EONBOT guide silhouette within the Command Centre. It is a guide, not a claim that AI work is active.
- A Command Board outside the canvas: current City mission stage, local crew status signals, safe work lanes, and a visible review-first handoff to Immersive Work Mode.
- A strict `W367` contract, source gate and unit tests.

## Privacy and truth boundary

The Command Board receives only safe local references. It never renders prompts, AI outputs, provider names/endpoints/keys, chat transcripts, files, Vault material, account details, payment records, or background-work details.

A cue is displayed only when the existing local presence model has recorded one. The empty state explicitly says that the City does not invent busy AI characters. Camera changes are local visual preferences. Native handoffs require an explicit visible user review and a second confirmation click.

## Art limitation

The new scene direction is still procedural geometry. **No GLB, GLTF, texture, animation, audio, music, voice, copied game asset, remote asset URL, or binary art pack is supplied by W367.** W365’s provenance ledger remains the prerequisite for any future binary asset delivery.

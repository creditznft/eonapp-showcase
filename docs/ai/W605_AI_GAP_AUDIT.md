# W605 AI gap audit — planned versus real

## Found in the authoritative W599/W604 source

- The text runtime already had route/product context, but no versioned, testable grounding pack covering the first answer across local and connected calls.
- An older `shared-memory.js` utility existed but was not in the model context path. It could not truthfully be called active unified model memory.
- Local text was guarded through user-started loopback runtime discovery and self-test.
- Creator Studio local image/video work was setup guidance; no active adapter, model picker, render, download, edit or post action was proved.
- A W592 benchmark existed, but it did not provide the full text/code/image/video/creator output matrix or a clear first-run grounding evaluation.
- Browser hardware classification could infer coarse device class but not reliable GPU VRAM; 16 GB system RAM could be mistaken for a workstation even with 4 GB VRAM.

## W605 closes

- Versioned public product grounding in compatible text calls.
- Explicit local memory with consent, secret rejection and shared context builder.
- Research truth contract—no direct local-model browsing or uncited current facts.
- Explicit output matrix contract and redacted opt-in loopback test script.
- VRAM-aware media plan separate from browser RAM classification.
- User-facing `/local-ai` controls to save/clear memory and inspect a realistic media test path.

## Still open

- A real cited web research connector.
- Actual API/provider output proof with owner-approved live credentials.
- A user-installed ComfyUI output proof on the owner’s machine.
- Image/video adapter implementation after local output proof.
- Creator Studio authorized edit pipeline and non-destructive media provenance.
- Cross-device encrypted memory sync, only after privacy/identity/persistence proof.

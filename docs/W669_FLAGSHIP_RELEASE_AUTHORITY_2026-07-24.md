# W669 — Flagship release authority

W669 is the stop rule for the W664–W668 recovery programme. It does not add another visual concept. It prevents source work, automated tests, a Preview, or a confident-looking report from being mistaken for the 9.5/10 owner acceptance.

## Source status

The local recovery programme can prove:

- canonical keyboard, D-pad and touch movement authority;
- overlap-safe district residency and transitions;
- explicit truthful functions for every shipped character, terminal, prop and landmark;
- a deterministic 5×5 streamed Expanse with a 3×3 interactive neighbourhood and practically unbounded seeded world grammar;
- one shared Pulse → Expanded Nexus → Spatial Living Nexus state;
- a simplified world-first Living Nexus gateway.

Passing these gates means **source-ready, human-proof-required**. It does not mean release-approved.

## Required owner evidence

1. Input authority at eight camera headings and after destination transfers.
2. Twenty minutes of continuous Core traversal without district popping or replacement glitches.
3. Exact click/E interaction for every visible functional asset; no Transit fall-through.
4. At least 25 Expanse cell-boundary crossings, varied coherent regions, Atlas recording and exact return.
5. Visible state continuity from Pulse to Expanded Nexus to Spatial Living Nexus.
6. Inspect, enter and return loops for all six authored Realms.
7. Clean page, console and first-party network diagnostics, bounded memory growth, recovery and usable frame pacing.

The required matrix is Chrome, Edge, Firefox and Opera; owner desktop and mobile landscape. The exact production SHA, candidate digest and deployment ID must be attached to the evidence.

## Release threshold

- overall owner score: at least 9.5;
- every scored category: at least 9.0;
- critical defects: zero;
- owner visual approval: explicit;
- owner GO: explicit.

Automation may collect evidence. It may not assign the owner score or approve production.

## Storage and workflow boundary

Local development and source certification require no Codex and no GitHub Actions artifacts. A later production upload may use the established zero-artifact deployment path only after the exact candidate has been built and human-reviewed.

Local-first choice

What “Local AI” means in EONAPP

Local AI is an optional route for people who want compatible AI work to stay on their own device. EONAPP checks what the browser and device can support before offering a local route. It does not assume that every phone or computer can run the same model, and it does not silently turn a cloud conversation into a local one.

When a supported local route is active, EONBOT labels that route so you can see what is being used. Local text, image and video capabilities are assessed independently because a device that can handle a small text model may still be unsuitable for local image or video generation.

Browser-local text

Local Lite for compatible devices

Local Lite is designed as the lighter browser-based option. EONAPP first checks practical device capabilities such as browser support, available graphics features and storage conditions. If the device is not a good match, EONAPP can keep Local Lite unavailable rather than forcing a large download or creating an unreliable experience.

Model downloads remain visible to you and can be cached by the browser where supported. Availability can vary between browsers, operating systems and device classes, so EONAPP treats local readiness as a capability check instead of a promise that every device will run the same workload.

Desktop runtimes

Use AI you already run on your computer

On supported desktops, EONAPP can work with compatible local runtimes such as Ollama, LM Studio and Jan. The setup flow is intended to hide unnecessary networking detail while still making the connection explicit. EONAPP checks the local connection before presenting it as ready, and a failed check does not silently fall back to a different provider.

This makes it possible to use models you choose and manage on your own computer while keeping EONAPP as the workspace around them. Model availability, speed and memory use depend on your local runtime, the model you installed and the hardware available to that runtime.

Control and privacy

You choose when data leaves the device

EONAPP separates local routes from connected AI providers. Files can be previewed locally, and attached text or code is included with a model request only when you choose to send the message. Connecting a hosted provider is a separate action and does not make Local AI a cloud feature.

Local processing also has practical limits: browser speech services can have their own device or browser behavior, local models can require significant memory, and clearing browser storage can remove downloaded model data. EONAPP therefore shows capability and setup state instead of presenting “local” as a blanket guarantee for every browser feature.

Choose the right route

Local when privacy and control matter; connected when you choose it

You do not need Local AI to use EONAPP. The normal AI setup can show the routes available to you, while Local AI remains an optional path. A lighter device can stay with supported hosted options, a capable browser can use Local Lite, and a desktop user can connect a local runtime. The goal is to make the trade-off understandable before work begins rather than hiding it behind automatic provider switching.

If you are unsure, use the readiness check below. It reports what this device can support and keeps model downloads or operating-system permissions visible. You can return to EONBOT at any time and change the selected route from AI setup.
